# 06counter 新版实现计划

目标：按用户提供的 17 节产品方案与 UI 图，实现「比计算器快，比 POS 简单」的本地收银 PWA。

架构：保留原生 HTML/CSS/JavaScript 和 GitHub Pages 部署。新版拆成状态模型、页面交互、导入和导出模块。legacy.html 保留旧版功能和激活代码；新存储键隔离旧数据，首次只迁移商品和布局，不把旧计数伪造成成交订单。

## 文件与步骤

- [x] `tests/model.test.mjs`：先验证金额精度、临时项、数量调整、成交快照、重复完成、存储失败、旧版迁移和非法导入。
- [x] `src/model.mjs`：金额以整数分计算，商品和订单保存价格快照；所有更改先持久化成功再替换内存状态。
- [x] `index.html`, `src/app.mjs`, `src/styles.css`：实现收银/商品/流水导航，当前订单、大数字展示、成功页、设置。固定订单栏；宫格小中大、不截断商品数、400ms 长按换位、拖动缩放与键盘替代操作。
- [x] `src/import.mjs`：本地 SheetJS 解析 xlsx/xls/csv，选择工作表、表头行、名称/价格列，完整预览与行错误；阻止非法价格、相同字段和无有效行导入。追加商品后自动出现在宫格。
- [x] `src/report.mjs`：按本地日期筛选订单，倒序流水和汇总；本地 jsPDF 生成带中文的分页 PDF，空日也可导出。
- [x] `sw.js`, `manifest.json`：缓存全部新版资源和本地依赖，兼容子目录部署；不自动跳过等待，以免收银过程中热替换模块。
- [x] `tests/browser.cjs`：移动端验证完整成交链、刷新恢复、导入两种 Excel、错误处理、宫格、数据备份恢复、PDF 下载以及离线启动；检查 320/390/768px 溢出。
- [x] `README.md`：本地运行、测试、数据迁移、依赖来源和发布注意事项。

## 验收例

15 元商品点两次、56 元商品点一次 → 3 件 / ¥86 → 展示 15 × 2 + 56 = 86 → 完成后恰好一条订单、购物车为空；刷新后流水保持。0.1 + 0.2 = 0.3；负值、空值、超过两位小数不静默舍入。存储写入失败不得显示收款成功或清空订单。

不加入分类、图片、库存、会员、支付方式、找零、折扣、账号或独立订单详情。数据清空需明确范围并二次确认。使用用户已提供的设计直接实施，不增加设计审批环节。

## 验证结果

- 8 项模型测试通过，涵盖金额、订单、失败回滚、恢复及迁移。
- Chromium 浏览器完整收款链、XLSX/XLS、CRUD、离线和备份测试通过。
- 边界浏览器测试覆盖无表头映射、临时金额独立订单、真实拖动/缩放、长名称/大金额、日期过滤；51 条流水生成 3 页 A4 PDF。
- 代码审查发现的无表头列数与空单临时金额入口已修复，窄屏大金额布局已增加回归测试。
- 真机 iPhone Safari/PWA 安装与下载体验仍需设备验收。
